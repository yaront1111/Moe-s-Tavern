# packages/moe-daemon/CLAUDE.md

Daemon internals. Project overview, build and test commands: root `CLAUDE.md`; tool contracts: `docs/MCP_SERVER.md`.

- **Adding/changing daemon MCP tools**: the only registry is `getTools()` in `packages/moe-daemon/src/tools/index.ts` — an unregistered tool is silently invisible to MCP. Tool dispatch is serialized through the global reentrant state mutex (McpAdapter and plugin WS handlers share it); a tool that parks for minutes must set `blocking: true` (currently `wait_for_task`/`chat_wait`/`wait_for_resource`) or it freezes every other tool fleet-wide. `submit_plan` also opts out for its bounded cached-Git lookup, serializing and revalidating each write attempt itself.
- **Task-size + verification gates** (both tunable/removable only in code or settings — they exist because prompt-only rules measurably don't hold): `submit_plan` warns past 8 steps / 5 distinct affectedFiles and hard-rejects past 12 / 10 (`settings.taskSizing`; logic in `util/planSize.ts`) with "split via moe-epic-breakdown/SPIDR" guidance; `create_task` guardrails are **all advisory — creation never hard-fails** (columnLimits at creation, meta-titled-row consolidation, and `taskSizing.maxTasksPerEpic` default 40 emit warnings only; `workerId` resolves the creator's role for `createdBy` attribution); task `dependsOn` (set at `create_task`, edited via `set_task_dependencies` — the architect/governor escape hatch) gates **WORKING-status claims only** (planning proceeds; missing/deleted ids count as satisfied); `complete_task` requires `verification: { command, exitCode: 0, outputTail? }`, persisted on the task and surfaced to QA via `get_context` for re-run auditing, and persists `summary` as `completionSummary`; `qa_approve` requires a `summary` of what was verified (persisted as `reviewSummary`) and is a **soft commit gate**: it returns `warnings[]` (`NO-COMPLETION-COMMIT` when no completion commit is recorded in the current work round: at or after the most recent rejection, else the first step start (`workStartedAt`), else `reviewStartedAt`, per `completionCommitsForReview` in `delivery/policy.ts` — the wrapper lands it seconds after REVIEW, so QA checks `task.commits` / `git show <sha>` first) plus `commitEvidence`, but always approves. `scripts/analyze-task-metrics.mjs` reports reopen/reject rates per plan-size bucket from `.moe/tasks/*.json` for tuning the thresholds (`--commits` buckets `feat|fix` / `wip` / `rescue` per task and lists unrecovered rescue refs).
- Dead-worker handling, four layers: every daemon (re)start purges the worker records that are neither recently active nor mid-execution and releases their tasks (a seat mid-execution is held instead — the restart hold below); graceful exits call `moe.deregister_worker` from the wrapper's exit trap (`moe-agent.{sh,ps1}`); a seat the JetBrains plugin launched is deregistered by the plugin itself (`DEREGISTER_WORKER` over `/ws`, acked with `WORKER_DEREGISTERED`) when its terminal tab is disposed — a tab close or IDE exit kills the wrapper before its trap can run — and again at every daemon connect for each launched seat whose tab is gone, so an IDE restart or crash frees every seat of the previous session (ids persist in workspace state `moe.launchedAgentSeats` until acked; seats launched outside the plugin are never touched); and a dead **CLI** under a still-live wrapper (one-shot `--print` exits at end_turn, killing background jobs) self-heals via the wrapper resume path — `claim_next_task` returns `hasNext:false` + `alreadyAssigned` and the wrapper relaunches the CLI onto the held task with a RESUME prompt (cap `MOE_RESUME_MAX_ATTEMPTS`, default 5, then a one-time #general escalation and idle). There is deliberately **no idle-based auto-release for WORKING/PLANNING** (the old 30-min worker-liveness sweep was removed — it yanked tasks off long-running coders): a hard-crashed worker's task stays assigned until daemon restart (plus up to `reconcileWindowMs` when the corpse still held an open attempt — the restart hold below cannot tell a dead runner from one about to reattach), `moe.deregister_worker`, or a manual/governor `release_task` — and its uncommitted bytes are not lost either way: the persisted per-task baseline makes the next session of that task (including the BLOCKED-hold and resume-cap idle paths) land a recovery checkpoint before any CLI launches. Task claimability keys strictly on the owner being missing from the worker map or explicitly `DEAD` (`isTaskClaimable`) — **never on idle time for WORKING/PLANNING**: a worker quiet past the 120s `isWorkerAlive` presence window (display-only, for `list_workers`/`chat_who`) keeps its task. **Restart hold + runner reattach**: every claim a wrapper makes records the runner's process identity (`processStartedAt` = `<wrapper pid>@<process start token>` plus `host`, computed once per wrapper process — it outlives every CLI respawn); a daemon restart parks each `running` attempt whose task is still assigned in `reconciling` and HOLDS the row; the wrapper's heartbeat sidecar gets `reattachRequired` (`attempt-reconciling`) and calls `moe.reattach_attempt` with the attempt id and generation it pinned at claim plus that identity, which returns the attempt to `running` (the main loop does the same right after the claim and right after the CLI exits, for a restart the sidecar did not see). A refusal (`ATTEMPT_IDENTITY_MISMATCH`: a respawned wrapper is a different process) is logged once and never retried; a seat that never reattaches is still given up after `reconcileWindowMs` (default 2h) and its row released. A match narrows WHICH process; it is never evidence that the process is alive. **REVIEW is the deliberate exception**: a QA owner silent past `reviewStaleTimeoutMs` (default 30 min, same default as `staleWorkerTimeoutMs`; both configurable per-project via `.moe/project.json` `settings`) has its REVIEW task released (unassigned, status stays REVIEW) so another QA can claim it — added because a hard-crashed QA with no graceful deregister isn't `DEAD` and would otherwise strand the task forever. Release routing (`nextStatusForRelease`, shared by every path): WORKING stays WORKING-unassigned so the next worker re-claims and resumes it (workers claim ONLY the WORKING column — BACKLOG is human-gated and invisible to agents), or →REVIEW if every step is already done; PLANNING/REVIEW stay put. The **blocked-timeout sweep is the one 'park' exception**: it routes in-flight tasks (PLANNING/WORKING/REVIEW) → BACKLOG deliberately, because the blocker is usually environmental and requeueing would claim-thrash the next agent into the same wall; humans un-park via `set_task_status` (BACKLOG→PLANNING/WORKING/REVIEW are all legal transitions). A dependency-waiting BLOCKED hold (`blockedOnTaskIds` set) under a timed-out worker is **unassigned but stays BLOCKED** (the auto-unblock only scans BLOCKED rows; a row left assigned to the timed-out corpse would be restored onto it — unclaimable and unprunable), and the dependency auto-unblock itself restores a still-assigned hold to its worker only while that worker exists, is not DEAD and still points at the task — else the task returns unassigned. The same sweep's stale-block `#governors` alert covers dep-less rows past `blockedTimeoutMs`, dep-waiting rows whose prerequisite is itself BLOCKED/BACKLOG (a cycle or a parked prerequisite — nothing auto-clears without a human), and dep-waiting rows past 2× the timeout. `claim_next_task`/`wait_for_task` hard-reject statuses outside PLANNING/WORKING/REVIEW — claiming a human-gated column (BACKLOG/AWAITING_APPROVAL/DONE) used to "succeed" without transitioning status and wedge the worker. `DEAD` workers are dropped from the UI and their records pruned once they own nothing.
- **Shared resources** (`state/resourceStore.ts`, tools `acquire_resource`/`release_resource`/`list_resources`/`wait_for_resource` — the last is `blocking: true`): daemon-owned admission control for exclusive-use infra (a benchmark box, a staging DB) replacing per-project marker files + pid probes. Leases are **task-keyed** (survive CLI respawns AND the restart worker purge; only a resource declared `releaseOnDeregister` drops a task's lease/queue entry when its seat deregisters, restoring a task BLOCKED on it), persisted in `.moe/resources/<id>.json`, granted FIFO-by-task-priority; undeclared ids auto-create (capacity 1, `maxLeaseMs` 24h — override via `settings.resources`). `report_blocked` with a `resourceId` first tries the lease (free → granted, no block), else queues + flips the task WORKING/PLANNING/REVIEW → `BLOCKED` (`blockedFromStatus` remembered); the grant path flips it back and that single status write is what wakes the fleet. `BLOCKED` is not agent-claimable; `nextStatusForRelease` keeps it BLOCKED on requeue (restart must not un-block) and BACKLOG on park; the blocked-timeout sweep **skips** resource-waiting BLOCKED tasks (their bound is the lease reaper: expiry force-release + orphan cleanup + grant onward, same 5-min sweep). Wrappers suppress CLI relaunch for `alreadyAssigned{status:BLOCKED}` without burning resume attempts.
