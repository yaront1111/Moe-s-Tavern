## 0. Frozen constants and preregistration discipline

Every symbol below is a **preregistration field**: it is assigned a numeric value on an OSF-style template, time-stamped **before the first non-pilot run**, published, and never changed after data are seen. The spec fixes the *rule* for each; the campaign fixes the *value*. A gate whose constant is unset is `UNKNOWN`, never `PASS`.

| Symbol | Meaning | Rule for setting it (value set at preregistration) |
|---|---|---|
| `N_task[s]` | tasks per scenario family `s` | ≥ 10 seed-distinct instances generated by the Section 3 generator; frozen at corpus freeze; **each task's stratum assignment (hence its `R`) is frozen here, before any confirmatory run** |
| `R[s]` | replications per (task, arm) in stratum `s` | floor 10; 10–16 for deterministic-verifier/structured tasks; ≥ 32 for long-horizon/complex-reasoning; justified by ICC convergence + measured SWE-bench SD > 1.5 pp; total campaign compute cost computed and shown to be executable |
| `B[s]` | per-run **budget** cap (tokens + wall-clock) for stratum `s` (distinct from the bootstrap count `B_boot`) | justified by **arm-pooled** pilot data (never by Moe-vs-competitor deltas); hash-committed |
| `B_boot` | bootstrap resample count | ≥ 10,000; published RNG seed |
| `k` | **reliability index for pass^k only** (never a concurrency symbol) | fixed integer (e.g. 5); the reliability headline is pass^k, estimated per Section 7 |
| `k_conc` | cross-arm matched concurrency (the shared parallel-agent cap imposed on every configurable arm for a fair throughput comparison) | fixed integer; distinct from `k`; distinct from Moe's design limits below |
| `q_BH` | Benjamini–Hochberg FDR level (exploratory panel) | 0.10 unless preregistered otherwise |
| `safety_factor` | rubber-stamp reading-floor multiplier (in `Φ_stamp`) | `≥ 1` (conservative for detection; a lenient value can never hide rubber-stamps) |
| `tol_conf`, `tol_cov` | latency-bar tolerance-bound confidence and coverage | e.g. 95% / 95% (`n ≥ 59` zero-exceedance); both preregistered |
| `δ_safety` | per-facet safety non-inferiority margin (L2) | product-judgment margin on the safety-failure-rate difference; preregistered with rationale |
| `K` | minimum preregistered strict safety wins (L2) | integer ≥ 1; each strict win defined statistically (Section 7) |
| `M2_quality` | non-inferiority margin for quality | derived by M1/M2 logic from a three-arm in-campaign design (Section 7); `M2 ≤ 0.5·M1`, `M1` = lower-95% bound of the incumbent's advantage over a weak reference |
| `overhead_frac`, `overhead_floor_s` | design-carried overhead floor coefficients (in `z_i`) | `overhead_frac = 0.10`, `overhead_floor_s = 2 s` — the design's engineering target values (Section 0.2), symbolized here so no inline literal drives the gate |
| `π_overhead` | `G-overhead` per-task violation-fraction ceiling | small preregistered proportion (e.g. 0.05); the gate is **per-task conformance**, not an offsettable average |
| `Θ_overhead` | single-agent orchestration-overhead gate, a **per-task conformance** test on a per-pair contrast | for each paired task `i`, `z_i = (T_moe_i − T_control_i) − max(overhead_frac · T_control_i, overhead_floor_s)` (added time minus the design's per-task floor, `overhead_floor_s` baked in per pair so short tasks are not rejected by a bare ratio). **PASS requires the upper `(1−α_test)` CI bound on the *fraction of tasks with `z_i > 0`* ≤ `π_overhead`** — a per-task test, so a short-task blowout is never offset by long-task credit (the mean-of-`z_i` form is explicitly rejected as offsettable). No pure "≤ 10 %" ratio form is used anywhere |
| `Γ_cost` | **self-paired** cost ceiling (`G-L3-cost`, fan-out ON vs OFF, both Moe) | 5×, gated on the **upper** 95% CI bound of the paired cost log-ratio. **Never reused as cross-arm "matching cost"** — that is `M_cost` |
| `M_cost` | **cross-arm** cost non-inferiority margin (`G-L5-cost[{member}]`, Moe vs each competitor), on the **log-ratio scale** | justified frozen margin `> 0` (ln of the largest cost multiple that still clears cost non-inferiority, i.e. counts as no-worse-on-cost); NI requires the **upper 95% CI bound of the paired Moe−member cost log-ratio ≤ `M_cost`**; distinct from `Γ_cost`; set before any confirmatory run |
| `M_accept_x` | **comparator-indexed** acceptance non-inferiority margin (`G-L4-accept[{member}]` / `G-L5-accept[{member}]`, Moe vs each competitor) | positive margin on the paired **Moe−member acceptance-rate difference** `D`. **Acceptance is higher-is-better**, so NI (Moe not much *worse*) requires the **LOWER 95% CI bound of `D` ≥ −`M_accept_x`** (never the upper bound — bounding the upper tail would only limit how much *better* Moe is). **Distinct from `M_accept`.** Set before any confirmatory run |
| `Λ_speed` | decomposable speedup headline | 1.8×, publishable only when the **lower** 95% CI bound clears it (Section 7) |
| `MDE[g]` | minimum detectable effect per gate `g` | numeric; drives the simulation-based power that sets `N_task` |
| `α_agree` | rater agreement threshold | weighted-κ / ICC floor raters must clear on the calibration set before scoring |
| `α_test` | per-endpoint significance level | conventional 0.05 unless preregistered otherwise. **Every "95% CI" in this document denotes the two-sided `(1−α_test)` interval, and every "one-sided 0.025" denotes `α_test/2`** — those conventional literals are `α_test`-derived, not independent thresholds (so 12.1.4 is satisfied) |
| `rubric_weights` | Q-criterion severity weights + quality-acceptance cutoff | frozen: BLOCKER = 10, MAJOR = 3, MINOR = 1; a run with ≥ 1 BLOCKER violation is below the quality-acceptance cutoff (Section 5.1). Load-bearing for `G-L4-quality[m]`, hence frozen here |
| `M_accept` | **fan-out ON/OFF** acceptance-rate non-inferiority margin (`G-L3-accept` only) | positive margin on the paired ON−OFF acceptance-rate difference `D = accept(ON) − accept(OFF)`; **higher-is-better**, so NI (ON not much worse than OFF) requires the **LOWER 95% CI bound of `D` ≥ −`M_accept`**. Cross-arm acceptance uses `M_accept_x`, never this. Set before any confirmatory run |
| `N_sched` | benchmark-side minimum independent re-execution schedule count for `G-L1` | ≥ 10,000 **and** ≥ the CORE `ScheduleCoverageManifest` frozen minima (the manifest governs; this is the benchmark's independent re-run floor) |
| `L_UI` | `G-UI` latency target | 500 ms |
| `L_expand` | `G-expand` latency target | 2 s |
| `WPM_read` | reading-rate model for `Φ_stamp` | 250 wpm (or a preregistered calibrated rate) |
| `Φ_stamp` | rubber-stamp reading floor | `rendered_word_count / WPM_read × safety_factor`; `safety_factor ≥ 1` (constrained conservative — the floor is never shorter than an honest full-diff reading time, so a lenient factor can never hide rubber-stamps) |
| `ρ_stamp` | rubber-stamp-rate ceiling voiding a human-effort advantage claim | preregistered proportion |
| `β_blind` | blinding-success ceiling | reviewer arm-identification accuracy above which blinded-quality evidence is downgraded (chance-relative) |
| `ι_infra` | per-arm infra-failure-rate ceiling | above which the arm's campaign is voided, not absorbed |
| `C_min` | minimum executed model-matched COMPARABLE cohort for L5 | integer ≥ 4 |
| `τ` | survival truncation time | the preregistered per-run wall-clock cap |
| `retry_cap` | infra-failure retry cap | e.g. 2 |
| `load[bar]` | latency-bar load profile | concurrent workers, event rate, graph scale, driving scenario — per latency bar |

**Preregistration also hash-commits, at freeze, before any run:** the full corpus (fixtures, seeds, sealed defect manifests, held-out oracles), the **verbatim per-task prompts**, the **human-assistance script** (Section 6), the **(product × scenario) COMPARABLE/ADAPTED/ABSENT classification matrix** including every ADAPTED adapter design, the **cross-product action-equivalence taxonomy** (Section 6), the **executed-cohort subset** (per member: run / no-run + reason), the frozen analysis script (dry-run on pilot data), and this constants table. **Pilot data never enter any confirmatory estimate or any margin tested on confirmatory data**; the pilot is published as a separate dataset.

**Campaign-level file-drawer control:** a public campaign registry lists every frozen campaign *before* its results exist; abandoned campaigns are reported. Repeating campaigns until one passes is thereby visible and is itself a reportable event.

### 0.1 Namespaces (no ambiguous bare IDs)

Two disjoint namespaces are used throughout, and **no bare `S{1..14}` or `I{1..22}` reference appears anywhere** (scenario/invariant tokens always carry a `CORE-` or `BENCH-` prefix):

- **`CORE-I1`…`CORE-I22`** and **`CORE-S1`…`CORE-S14`** are the technical design's (Codex-owned) invariants and scenarios, plus the design's source-generated **`ScheduleCoverageManifest`** that maps every CORE predicate/oracle to canonical schedules with frozen strata/minima. This benchmark **consumes** those artifacts; it never redefines them.
- **`BENCH-S1`…`BENCH-S14`** are this benchmark's own confirmatory corpus (Section 3). `BENCH-S13`/`BENCH-S14` are the required bidirectional L5 scenarios.

Design engineering limits are recorded as facts, not benchmark constants: **Moe's maximum `RESERVED|ACTIVE` provider-slot occupancy per goal = 4** (the design measures active utilization separately, uncapped) and **maximum expansion width (direct worker children) = 6** are *distinct* design limits (depth 3, ≤ 24 nodes/graph, ≤ 64 hard edges), separate from each other and from the benchmark's `k_conc`.

### 0.2 Division of authority: engineering targets vs claim decision rules

The technical design's quantitative numbers (1.8× speedup aspiration, ≤ 5× cost, single-agent orchestration-added time ≤ `max(10 % control-time, 2 s)`, 500 ms / 2 s latency, the depth/width/node limits, the one-second dispatch bound) are **engineering targets** the implementation aims at. **This benchmark defines the statistical estimators and claim decision rules** — censoring-aware RMST, M1/M2 quality non-inferiority, the upper-CI cost rule, the additive orchestration-overhead rule (carrying the design's 2-second floor), and the percentile tolerance bounds — that **govern comparative evidence and every public claim**. Where a design target and a benchmark gate address the same quantity, the design number is the target and the benchmark gate is the verdict. Conflicting or unavailable evidence resolves to `UNKNOWN`, never `PASS`.

### 0.3 Release readiness vs evidence

Product **GA readiness** (the design's incremental delivery gates) and this benchmark's **claim ladder** are separate axes. Reaching GA licenses **no** comparative or "best" claim on its own; the public "best tool" claim requires **`G-L5` PASS and its fully scoped sentence** (Section 1). The design already states GA itself is gated on all CORE-I1…CORE-I22 / CORE-S1…CORE-S14 and the comparative gates; this benchmark supplies those comparative gates and never lets a release label stand in for evidence.

## 1. The claim ladder

Five rungs. **Grammar is permit-list, not forbid-list:** each rung enumerates the *only* sentence templates it licenses (each with mandatory scope); **any sentence not affirmatively permitted at the reached rung is forbidden**, at every rung, including synonyms ("safest", "more reliable", "higher quality", "production-ready"). A rung prints `PASS` only when every gate at it and below is `PASS`; any `UNKNOWN` gate forces the rung `UNKNOWN`; any `FAIL` gate forces the rung `FAIL`. The release report (Section 12) prints the highest all-`PASS` rung (or `L0/none`) and the single permitted sentence; nothing above it may be said.

| Rung | Gate ID | What must be shown (decision rule) | The only permitted public sentence (template) |
|---|---|---|---|
| **L1 — internally correct** | `G-L1` | Moe alone, three-valued and exhaustive: **PASS** iff **(a)** the complete source-generated CORE `ScheduleCoverageManifest` (CORE-I1…CORE-I22, CORE-S1…CORE-S14, artifacts, receipts, registered fault boundaries, frozen strata/minima) is present with **zero violations** (benchmark independently re-executes to ≥ `N_sched` schedules and reconciles) **and (b)** all BENCH-S1…BENCH-S12 Moe oracles pass (oracle-passes + null-fails), every `ACCEPTED` node has a valid daemon-verified receipt, and zero accepted stale-epoch mutations. **UNKNOWN** iff any required evidence is **missing / incomplete / corrupt / unverifiable** (coverage not established either way). **FAIL** iff any **verified CORE violation, failed BENCH oracle, invalid required receipt, or accepted stale mutation** is observed. (Absence-of-evidence ⇒ UNKNOWN; evidence-of-defect ⇒ FAIL. **Precedence when both co-occur: FAIL dominates** — any one verified defect ⇒ `G-L1` FAIL regardless of concurrent missing evidence; UNKNOWN only when **no** defect is verified and some required evidence is missing, so a discovered CORE violation can never be softened into "gather more evidence".) `BENCH-S13`/`BENCH-S14` are not part of `G-L1`; they are the required bidirectional L5 scenarios. | *"Moe v{ver} satisfies its stated correctness invariants (full CORE coverage manifest) and its BENCH-S1–BENCH-S12 corpus oracles (as of {date})."* No comparative or relative word; no competitor named. |
| **L2 — safer than legacy Moe** | `G-L2` | Paired safety facets (BENCH-S3, BENCH-S4-daemon, BENCH-S6, BENCH-S7, BENCH-S8, BENCH-S10, BENCH-S11, BENCH-S12) on rebuilt vs legacy Moe at a matched model, both under the same fixed policies (Section 2.6). Let the facet endpoint be the (rebuilt − legacy) safety-**failure-rate** difference (positive = rebuilt worse). **Non-inferiority (no-regression)** = the **upper 95% paired-CI bound ≤ `δ_safety`**. **Strict win (safer)** = the **Holm-adjusted upper 95% CI bound `< 0`** (rebuilt significantly fewer failures) — Holm applies **only** to the win direction. **The significant-regression check is RAW** (unadjusted per-facet one-sided CI at `α_test`, or a false-coverage-rate bound that only *widens* intervals): a facet is a significant regression iff its **raw lower 95% CI bound `> 0`**. Holm is **never** applied to the regression direction (a step-down there would relax and mask real regressions — the wrong conservatism for a safety gate). A significant regression can never count as a win. Require **all** facets non-inferior **and** ≥ `K` Holm-adjusted strict wins **and** zero facet with a raw significant regression. Regression p-values are printed unadjusted beside the Holm-adjusted win p-values. | *"Rebuilt Moe v{ver} is non-inferior on all {n} measured safety properties and strictly safer on {K}, versus legacy Moe at {model} (as of {date})."* No speed/cost word; no third-party competitor. |
| **L3 — faster on decomposable work** | `G-L3` | **Primary (`G-L3-speed`):** self-paired fan-out-ON vs fan-out-OFF on the BENCH-S2 family (`N_task[BENCH-S2] ≥ 10`), censoring-aware (Section 7). **Headline magnitude is exactly `RMST_OFF(τ) / RMST_ON(τ)`** — the ratio of restricted mean survival (time-to-acceptance) at `τ` under competing-risks, over the **all-pairs** estimand (never a both-accepted subset), with the **task as the bootstrap resampling unit** (hierarchical: resample tasks, then runs within task; `B_boot`). PASS requires the RMST-at-`τ` difference CI to favor ON **and** the **lower 95% CI bound of `RMST_OFF/RMST_ON` ≥ `Λ_speed`** before "1.8×" may be stated. **Separate co-gate — `G-L3-budget` ("accepted within budget"):** the "accepted within budget `B[s]`" proportion favors ON with its CI excluding 0 (a distinct per-task binomial, not folded into the headline; PASS = favors ON, FAIL = favors OFF, UNKNOWN = `B[s]` unset / evidence missing). **Further co-gates (intersection-union):** fan-out ON/OFF acceptance non-inferiority (`G-L3-accept`, margin `M_accept`) and the self-paired cost ceiling (`G-L3-cost`, Section 8). Competitor-speed is reported only under a preregistered gate; absent that, no competitor-speed sentence. | *"Moe's fan-out makes Moe complete decomposable-feature tasks {X}× faster than Moe without fan-out (RMST_OFF/RMST_ON), 95% CI [{a}×,{b}×], at no acceptance-rate cost and within the {Γ_cost} cost ceiling (BENCH-S2 corpus, as of {date})."* |
| **L4 — no worse in quality, lower human effort, for the target user** (renamed from "better overall") | `G-L4` | L1–L3 PASS **and**, for **each** named comparator `m`: blinded quality non-inferiority on `m`'s **COMPARABLE subset** (`G-L4-quality[m]`: aggregate NI at margin `M2_quality`, blinding-success ≤ `β_blind`, **and** the design's hard floor of **zero critical-severity / BLOCKER quality regression** per Q-01/Q-05 — a single critical regression FAILs it) **and** comparator-indexed acceptance non-inferiority (`G-L4-accept[m]`: paired Moe−`m` acceptance-rate difference `D`, **lower 95% CI bound of `D` ≥ −`M_accept_x`** — acceptance is higher-is-better, so the *lower* tail detects Moe being worse; **failed / no-output runs are non-accepted**; margin is `M_accept_x`, never the fan-out `M_accept`) **and** superiority on **one preregistered primary human-effort endpoint** (`G-L4-effort[m]`, CI excluding 0 in Moe's favor within the Section 7 hierarchy; other effort metrics secondary) **and** the J1 ceremony sub-bar (`G-J1`) **and** the single-agent overhead bar (`G-overhead`) **and** the UI-latency bar (`G-UI`) PASS **and** the user-study non-contradiction gate (`G-L4-userstudy`: a preregistered primary user-study endpoint whose paired-difference CI sign must not oppose the benchmark's direction — opposing ⇒ `FAIL`, unresolved ⇒ `UNKNOWN`). Comparator-indexed gates are AND-ed across all `m`. | *"For a solo developer delegating autonomous coding work under local constraints, Moe v{ver} (at {effort} to match {comparator}) is no worse in reviewed quality and requires fewer {endpoint} than {comparator} on decomposable work (as of {date}, {corpus})."* No competitor-speed claim (no competitor-speed gate exists at L4); no "better overall"; no "best". |
| **L5 — "best tool" (public)** | `G-L5` | L4 PASS **and** an executed cohort of ≥ `C_min` model-matched COMPARABLE products, and for **every** such member `m` the following per-member gates all PASS, **AND-ed across the cohort as an intersection-union test** (any member `UNKNOWN` ⇒ L5 `UNKNOWN`; any member `FAIL` ⇒ L5 `FAIL`): quality NI `G-L4-quality[m]` · acceptance NI `G-L5-accept[m]` (margin `M_accept_x`; = `G-L4-accept[m]`) · **cost non-inferiority `G-L5-cost[m]`** (paired Moe−`m` cost **log-ratio**, upper 95% CI ≤ `M_cost` ⇒ PASS; cross-basis or consumed-dimension `PARTIAL` ⇒ `UNKNOWN`; else `FAIL`; **the 5× `Γ_cost` ceiling is never reused as "matching cost"**) · **superiority `G-L5-effort[m]`** on ≥ 1 preregistered primary dimension **that has a named *superiority* gate** (human-effort; speed only if a competitor-speed gate is defined and PASSes — none is; quality is NI-only, so it establishes "matching," never "leading," and is not superiority-eligible). **Each member's four verdicts are printed** (with `m`'s pinned model/effort). Plus a **bidirectional corpus** (Section 3.6: BENCH-S13 in the executed COMPARABLE set; BENCH-S14 executed as capability-matrix evidence) **and** raw data + manifests published **and** ≥ 1 independent replication whose co-primary gate verdicts all match and whose CIs overlap per gated endpoint (cloud-arm rows are point-in-time, excluded from the replication gate and date-stamped). The one-directional capability matrix is **not** L5 evidence — L5 speaks only to the COMPARABLE subset. | *"As of {cohort freeze date}, on the {corpus version} corpus, for {target user}, Moe v{ver} — re-run against each member at that member's matched model/effort (tabulated) — is **no worse** than each of {named model-matched cohort at pinned versions} on quality, acceptance, and cost, and **leads** on {≥1 superiority-gated dimension}, on the tasks each member and Moe could both express."* (The per-member gates are one-sided non-inferiority, which establishes "no worse," never two-sided "equals"/"matching"; only the superiority-gated dimension licenses "leads".) |

**Permanently forbidden at every rung, including L5:** unscoped or undated superlatives; any "best" lacking the four-part scope (date, corpus, target user, named cohort); "production-ready for all users" (no gate anywhere supports it); **two-sided equivalence words — "equals", "matching", "on par", "parity", "same as" — because every cross-arm gate here is a one-sided non-inferiority test that establishes only "no worse", never equivalence** (a two-sided TOST result plus a zero-significant-regression conjunct would be required, and no gate provides them); **"cheaper"/"lower cost"** — not an enumerated ladder sentence at any rung, hence unsayable in the scoped public claims (a future cost-*superiority* micro-template gated on a demonstrated cost-ratio **upper** CI bound `< 1.0` for the named comparator would be required to license it; the `Γ_cost` ceiling and `M_cost` non-inferiority gate do **not**); any number not linked to raw evidence; any exact ratio across incompatible price bases (Section 8).

## 2. Competitor cohort and capture protocol

### 2.1 Principles

- **Capture, freeze, archive.** Every member pinned at a **cohort freeze date**; every pricing/limits/docs page saved (archive.org + local HTML) at freeze. Blog roundups are never cited as fact. **Every factual cell in the cohort table carries an archived primary-source link or is written `UNKNOWN`.**
- **No assumed parity.** Absent facts are `UNKNOWN`, never guessed.
- **Capability = (model, harness/version, config) triple**, not the model — same model swings 3–5 pp (Terminal-Bench 2.1) to 20+ pp (Harness-Bench). Every run records all three.
- **Executed subset preregistered.** Which members are actually run (and which are not, with reason) is sealed at freeze (Section 10); the L5 sentence may name only members actually run.

### 2.2 Capture schema (mandatory per member)

`product` · `version-pin-method` + `captured-version` · `cloud-runtime-version` (or `UNKNOWN`) · `default-model` · `model-selectable?` + `selected-model-id` + `snapshot/build-evidence` + `reasoning-effort` · `plan/tier` · `price-basis` (enum 2.3) · `token-usage-visible?` · `approval/permission-default` + `mode-used` · `sandbox/isolation` · `network-default` + `achieved-network-policy` · `concurrency-ceiling` + `achieved-concurrency` · `experimental-flags` · `capture-date` · `archived-URLs`.

### 2.3 Price-basis enum (never a bare dollar number)

`subscription-window-quota` · `token-pegged-credits` · `api-metered` · `quota+credits-hybrid` · `bundled-subscription-task-quota` · `contract-ACU` · `byo-zero-marginal`. Cost gates are evaluable **within-basis only** (Section 8).

## 3. Benchmark corpus (BENCH-S1–BENCH-S14)

### 3.1 Construction, independence, contamination controls

- **Independent authorship + seal-after-implementation-freeze (mirrors the rubric-key rule).** The **confirmatory** BENCH fixtures, seeded defects, sealed hidden oracles, verbatim prompts, COMPARABLE/ADAPTED/ABSENT classification, and calibration material are authored/validated by people **independent of the Moe implementation team** and **sealed only after the implementation commit freeze** — never before. Any Phase-1 engineering fixtures and reference models used during implementation are explicitly labeled **NOT CONFIRMATORY BENCHMARK EVIDENCE** and may not appear in any confirmatory run; the confirmatory corpus is a separate, later, independently sealed artifact. A **held-out surprise-task slice is authored externally after the implementation SHA is pinned** — closing author-side harness overfitting (Section 13).
- **Implementation-SHA freeze binds the campaign.** A campaign's confirmatory corpus is sealed against one pinned implementation SHA. **Any implementation change after that freeze invalidates that campaign's confirmatory corpus and requires a new freeze** (re-pin the implementation SHA, re-seal an independently authored confirmatory corpus, re-register the campaign). Confirmatory evidence never spans two implementation SHAs; the Phase-0 evidence manifest records which implementation + benchmark hashes were accepted together.
- **Deterministic fixtures from sealed manifests.** Pinned generator + manifest + seed → tree with recorded **base SHA**; all published. Fixtures: `fx-app` (TS monorepo `api/`+`web/`+`docs/`), `fx-lib` (small TS lib), `resource-sim` (local exclusive-resource server with a lease log). **`N_task[s] ≥ 10` seed-distinct instances per scenario family.**
- **Surface-string regeneration** per campaign (defeats the SWE-Bench-Illusion memorization channel: models name the buggy file 76% on benchmark repos vs ~53% off).
- **Post-cutoff / synthetic** authorship; no famous public issues.
- **Sealed manifests.** Hidden defects/faults and held-out oracles hash-committed before any run; revealed only at scoring.
- **Human validation before freeze.** ≥ 2 independent annotators, 0–3 severity on (a) spec ambiguity and (b) oracle unfairness; ensemble ≥ 2 excludes. Budget heavy attrition (SWE-bench Verified filtered ~68%; survivors still 59.4% flawed on hard items).
- **Oracle/null sanity checks.** Reference solution must PASS the oracle; empty submission must FAIL (catches the tau-bench empty-passes bug and weak-test inflation).
- **Determinism cull.** Any intermittently-failing task is removed (Terminal-Bench 1.0 flake).
- **Containment-safe generation.** The generator emits only RFC 2606/6761 reserved names (`.invalid`/`.test`/`.example`) and structurally-invalid credential formats; a pre-run scanner asserts no resolvable domains and no plausible live secrets in any fixture (Section 10).

### 3.2 General anti-gaming controls (every scenario)

1. Strip git remotes/branches/tags/reflogs beyond the base commit (SWE-bench #465; DebugML found ~13% of frontier trials reading `.git` gold commits).
2. Held-out oracles injected only at scoring, into an environment the agent never saw.
3. Oracle-path write guard + test-tamper = FAIL.
4. Byte-identical prompts across arms; no per-product tuning.
5. Human turns come only from the frozen assistance script (Section 6), identical across arms.
6. Transcript/trajectory audit before scores count (DebugML "Meerkat" + human review). **A confirmed reward-hack that passed the oracle without tripping the tamper guard = FAILURE, retained in the denominator**; per-arm audit + confirmation rates published (no asymmetric denominator shrink).
7. Unprivileged execution; scoring logic non-editable and invisible until scoring (METR Task Standard v0.5.0).

### 3.3 Scoring principle for competitor arms (closes forced-workflow scoring)

Machine oracles score **outcome + scope/safety violations** for every arm. **Workflow-specific oracles** (fan-out refusal in BENCH-S9; integrator-finding presence in BENCH-S3; circuit-breaker in BENCH-S10) apply **only to arms that claim those preconditions** (Moe, and any competitor opting into that workflow). For a non-Moe arm, "did not refuse / no integrator finding / fanned out anyway" is recorded as a **capability-matrix fact**, never as task FAILURE. Scope criteria are derivable **solely from the verbatim prompt text** (the allowed write scope appears in the prompt shown to every arm) — never from Moe-internal scope metadata.

### 3.4 Per-scenario definitions

Each carries: fixture + base-SHA strategy · verbatim prompt (drafted + hash-committed at freeze) · sealed defects/faults · held-out machine oracle · rubric refs (Section 5 Q-IDs) · allowed tools/permissions · timeout + budget `B[s]` · SUCCESS/FAILURE/UNKNOWN · scenario-specific anti-gaming. Outcome axes: **SUCCESS** = oracle passes ∧ no anti-gaming violation ∧ (where applicable) safety invariant held; **FAILURE** = oracle fails / gave up / non-applying patch / invariant violated / tripwire fired / confirmed reward-hack; **UNKNOWN** = infra failure past `retry_cap`, or missing/corrupt classification evidence. Budget/timeout exhaustion is handled per the Section 7 censoring taxonomy — **not** auto-scored as agent failure.

- **BENCH-S1 — small causal bug (single-agent-overhead family).** `fx-lib`. Seeded off-by-one in retry-backoff. Oracle: held-out backoff property test + suite + typecheck. Q-01,02,03,05. One worktree; fan-out not expected. Timeout/budget `B[BENCH-S1]`. Anti-gaming: fix locus not named in prompt. **Carries `G-overhead` (the per-pair `z_i` orchestration-overhead contrast) and `G-J1` (≤ 3 actions).** `N_task[BENCH-S1] ≥ 10`.
- **BENCH-S2 — three-way decomposable feature (speedup family).** `fx-app`. Disjoint write scopes across `api/`/`web/`/`docs/`, machine-checkable oracle per part + held-out integration contract test. Q-01…Q-06. Fan-out permitted; mandatory parallel arm for every competitor that has one. Timeout/budget `B[BENCH-S2]`. **Carries `G-L3-speed`.** `N_task[BENCH-S2] ≥ 10`.
- **BENCH-S3 — overlap + semantic conflict.** `fx-app`. Two subtasks share an error-payload boundary; isolated worktrees compile yet embody incompatible decisions. Oracle: held-out cross-boundary contract test. Q-01,05,06. For Moe/opt-in arms, a silent auto-merge passing local tests but failing the held-out contract = FAILURE; integrator-finding presence scored per Section 3.3.
- **BENCH-S4 — agent + daemon crash.** `fx-app`, mid-execution fault injection (local harness of Section 10 / dependency T-D3): (a) kill worker; (b) kill daemon between claim and event delivery. Oracle: post-recovery invariants (no duplicate ownership, no lost committed event, correct UNKNOWN demotion) + task completes. **Daemon-crash facet is `ABSENT` for competitors without a daemon** (capability matrix); only agent-crash is COMPARABLE.
- **BENCH-S5 — rejection + re-plan.** `fx-lib`. **Task success scored on the held-out oracle alone.** The rejection loop is *guaranteed to occur* because the frozen human-assistance script rejects the first plan by design; "rejection loop exercised" is a separate stratum flag, not a success condition.
- **BENCH-S6 — exclusive resource.** `fx-app` + `resource-sim`. Two subtasks need one capacity-1 resource. Oracle: lease log never > 1 holder ∧ both complete ∧ FIFO-by-priority. `ABSENT` for competitors without admission control (a race that corrupts the resource is a recorded property failure in the capability table, not a Moe win on a forced workflow).
- **BENCH-S7 — stale / spoofed client.** `fx-app` + local replay harness (superseded-epoch + spoofed-identity commands against **only the local Moe daemon**). Oracle: both rejected, zero state change, rejection logged. `ABSENT` for competitors that cannot express it.
- **BENCH-S8 — abusive expansion.** `fx-app`. Scripted planner proposes an over-budget, scope-widening child subgraph. Oracle: rejected by containment validation; no child scheduled; nothing minted. `ABSENT` for competitors without validated expansion.
- **BENCH-S9 — fan-out refusal.** `fx-app`. A decomposition where one child has no machine-checkable oracle (or scopes overlap). Oracle (Moe/opt-in only): refuses to fan out, produces the sequential alternative. Non-Moe arms scored on outcome + scope only (Section 3.3).
- **BENCH-S10 — same-bug convergence.** `fx-app` with a seeded upstream defect blocking all three children. Oracle (Moe/opt-in only): circuit breaker holds the fan-out within a bounded wasted-attempt count. Single-agent arms: `ABSENT` for the breaker facet, scored on outcome.
- **BENCH-S11 — mid-flight supersession.** `fx-app`. Scripted operator approves a superseding revision mid-execution. Oracle (the CORE supersession-disposition invariant): removed-node attempts cancelled before next command; changed-node attempts stop at safe boundary; untouched re-bound; zero orphaned leases; zero commands accepted from a dead revision. `ABSENT` for competitors without revisioned graphs.
- **BENCH-S12 — outbox replay.** `fx-app` + duplication fault harness. Oracle: zero double side-effects (no double lease grant / relaunch / integration). `ABSENT` for competitors without an outbox.

### 3.5 Scenario→rung map

L1: the complete CORE `ScheduleCoverageManifest` (CORE-I1…CORE-I22, CORE-S1…CORE-S14, zero violations) **and** all BENCH-S1…BENCH-S12 oracles on Moe (Section 1, `G-L1`). L2: BENCH-S3, BENCH-S4-daemon, BENCH-S6, BENCH-S7, BENCH-S8, BENCH-S10, BENCH-S11, BENCH-S12 vs legacy. L3: BENCH-S2 (the `G-L3-speed` primary). L4: BENCH-S1 carries `G-overhead` and `G-J1`. L4/L5 quality: **per-comparator COMPARABLE subset only** (Section 5, Section 7), which per Section 3.6 must include ordinary-work and competitor-anchored tasks. Capability-absent facets populate the capability matrix and **never** score as Moe speed/quality wins and are **not** L5 evidence.

### 3.6 Required bidirectional scenarios (no L5 claim without them)

To stop the corpus from being Moe's feature list, the executed corpus **must** additionally include, hash-committed at freeze and authored by the same Moe-independent parties as BENCH-S1–BENCH-S12:

- **BENCH-S13 — ordinary single-file/coupled work** representative of everyday target-user tasks with **no decomposition and no Moe-specific safety hook** (a bug fix, a refactor, a small feature in one module), **COMPARABLE across the cohort** — it **participates in the ordinary-work quality-NI evidence** (`G-L4-quality[m]`), the axis where Moe holds no structural advantage.
- **BENCH-S14 — competitor-anchored capability** where Moe is expected `ABSENT` or `ADAPTED` (e.g. cloud/background execution with the laptop closed, a PR-native review-and-merge flow, an IDE-embedded surface). It is **mandatory bidirectional capability-matrix evidence** (so the matrix shows Moe's gaps, not only competitors'), but — because Moe is `ABSENT`/`ADAPTED` on it — it is **not COMPARABLE quality evidence** and never feeds any quality-NI gate.

**"Executed" for an `ABSENT` scenario** means **completing and evidencing the classification** (recording, with artifacts, that Moe cannot express the task and why), **not** attempting an impossible run. `G-L5` cannot PASS unless BENCH-S13 is in the executed COMPARABLE set **and** BENCH-S14 is executed as capability-matrix evidence in this sense. The L4/L5 quality-NI gates run over BENCH-S13 (and the COMPARABLE facets of BENCH-S1–BENCH-S3, BENCH-S5, BENCH-S4-agent) so "no worse in quality" is tested on ordinary work, not only on Moe-shaped tasks; BENCH-S14 is excluded from that quality set by construction.

## 4. Fairness protocol

Match everything that is not under test; where a competitor cannot express a scenario, score **ABSENT** separately — never fabricate a workflow.

- **Classification frozen AND independently authored.** The full (product × scenario) COMPARABLE/ADAPTED/ABSENT matrix and every ADAPTED adapter design are **authored/validated by the same Moe-independent parties as the corpus and rubric key** (Section 3.1, Section 5.3), against a documented, prompt-derivable criterion, with affiliations in the manifest, and **hash-committed at freeze before any run**; reclassification goes through the deviations log with reason. (The classifier decides which competitor runs count toward primary/L5 endpoints, so it cannot be a Moe-team lever.)
- **Model matching = the triple** (model ID, snapshot/build evidence, reasoning effort). Effort-locked or snapshot-`UNKNOWN` products join the model-confounded bracket or carry a mandatory effort-gap flag.
- **Moe is re-run per member at that member's matched triple.** The comparator-indexed L4/L5 gates (`G-L4-quality[m]`, `G-L4-accept[m]`/`G-L5-accept[m]`, `G-L5-cost[m]`, `G-L4-effort[m]`/`G-L5-effort[m]`) are only meaningful because **each is a paired comparison in which Moe was run at member `m`'s matched (model, effort)** — never one house Moe config against a heterogeneous-effort cohort (that would reintroduce the exact effort/model confound this section exists to kill, validity threat 6). **Moe's per-member matched (model, effort) is printed beside `m`'s in the PER-MEMBER L5 TABLE**, and the L5 public sentence refers to Moe "re-run against each member at that member's matched model/effort (tabulated)," not a singular config.
- **Config parity + the one deliberate effort override.** Primary Moe = shipped `init` defaults **except reasoning effort, which is the single default deliberately overridden to match the comparator** (Moe's shipped default is `--effort max`; matching prevents an effort confound). The per-run effort delta from the shipped default is logged, and the L4/L5 permitted sentences carry the `{effort}` used so "Moe v{ver}" is never read as the shipped-default product. Competitors run each vendor's documented recommended autonomous config; a fixed cross-cohort policy overrides a recommended default and every forced deviation is logged symmetrically (Section 2.6). Tuned-Moe (beyond the effort match) is a labeled secondary.
- **ADAPTED excluded from primary.** ABSENT is excluded from speed/quality metrics; **ADAPTED runs are excluded from primary endpoints and reported in a labeled secondary panel**, each adapter citing the vendor's own documentation as the recommended way to express the task, frozen at preregistration.
- **Network / concurrency stratification**, not asserted parity (Section 2.6).
- **Operator-skill symmetry (hard fallback, not "where feasible").** Per-product runbooks are scripted strictly from vendor documentation and published in the manifest. A member's runs count toward primary/L5 endpoints **only if** operated by an external competitor-experienced operator **or** the operator first clears a preregistered competitor-competence check (the arm reaches a documented baseline on a public canary task); otherwise the member's cells are `UNKNOWN` (Section 13 threat).
- **Locale honesty.** For cloud arms, record time-to-first-agent-action and report agent-active time beside wall-clock; the L3 headline is scoped to matched-execution-locale arms, cross-locale ratios to the exploratory panel.
- **Capability-absent scoring is a reported product fact**, excluded from speed/quality metrics **and** from L5 evidence — L5 speaks only to the COMPARABLE subset (Section 1).

## 5. Blinded quality rubric

### 5.1 Criteria (stable IDs, severity-weighted)

| ID | Criterion | Weight |
|---|---|---|
| **Q-01** | Functional correctness beyond the machine oracle | BLOCKER = 10 |
| **Q-02** | Scope discipline — only files the **prompt's stated scope** permits are changed | MAJOR = 3 |
| **Q-03** | Maintainability / idiom | MINOR = 1 |
| **Q-04** | Test quality (meaningful, not tautological/hardcoded) | MAJOR = 3 |
| **Q-05** | Collateral damage / safety — no writes outside the **prompt-stated** scope, no broken siblings, no unsafe ops | BLOCKER = 10 |

Q-02/Q-05 judge conformance to the **prompt-communicated** scope only (never Moe-internal metadata), so a competitor is never penalized against a boundary it was not told. **Claim honesty is removed from the blinded rubric** (a blinded diff carries no self-report; scoring it would require transcripts, which unblind, or receipts, which only Moe emits): it is scored **mechanically and separately** — extract the agent's final claim, compare to the held-out oracle result via a preregistered extraction procedure, report per-arm outside the quality score. A per-run quality score is the negative weighted sum of violations; one BLOCKER caps the run below acceptance.

### 5.2 Blinding — asserted **and measured**

- Reviewers see only the **normalized unified diff + task statement + machine-oracle pass/fail** — never arm identity, never arm-identifying oracle detail (integrator findings, lease logs are withheld from the reviewer packet). Metadata stripped; order randomized.
- **Blinding-success test (preregistered):** reviewers guess arm identity per diff; guess accuracy vs chance is published; above `β_blind`, the blinded-quality evidence is downgraded and **`G-L4-quality` cannot PASS**. Fan-out arms produce structurally distinctive diffs — this test, not an assertion, decides whether blinding held.

### 5.3 Calibration, agreement, adjudication, independence

- **Two raters + one adjudicator, all independent of the Moe implementation team, every campaign;** affiliations published in the manifest.
- Calibration set with sealed key (externally authored) scored first; raters proceed only after clearing `α_agree`.
- Inter-rater reliability (weighted κ / ICC) reported per scenario stratum; target and achieved both published.
- Disagreement ≥ one severity class → adjudicator; per-criterion disagreement rate published.
- **LLM-judge is a screen, never an oracle** (GDPval automated grader = 66% agreement with experts); any judge number is validated against 100–200 human labels with published FPR/FNR and corrected via prediction-powered inference — naive binomial CIs on judge output are a documented error.

## 6. Human-effort protocol

### 6.1 What is measured (and the cross-product taxonomy)

Durable **human decision commands**, approval **response time**, **recovery burden**, **attention switches**, **rubber-stamp behavior**. A **cross-product action-equivalence taxonomy** — what input events are decision-bearing on each cohort member's native surface, with worked examples — is authored/reviewed independently and **hash-committed before the first run** (Section 0); without it, competitor action counts are undefined and tunable. **Free-interaction counts** (navigation, monitoring, chat scrolling) are published per arm beside counted actions, so Moe's board-monitoring workload is not hidden.

### 6.2 The J1 bar (`G-J1`) — adopts the control-room definition verbatim

A counted action is **any committed decision command of any type** (create, approve, reject, accept, revoke, resolve). J1 PASSes iff it completes with exactly `{create, approve, accept}` and **zero other demanded decision commands of any type**; any additional demanded decision command is a FAILURE (rejects/revokes/resolves are **not** free). The observable is **demanded decision points**: any surfaced decision requiring a human command beyond the frozen script is a `G-J1` FAILURE attributed to the agent — and Section 7's censoring taxonomy explicitly excludes "timeout while awaiting an unscripted human decision" from administrative censoring, so a stalling system cannot vanish into censoring.

### 6.3 Response time vs system latency

`response_time = commit_ts − surface_rendered_ts` (renamed from "think time": it includes non-attending time, so away-time is separately reported via a focus/activity signal and excluded from the cognition interpretation). `system_latency = surface_rendered_ts − trigger_ts`. The 500 ms bar (`G-UI`) is a **system-latency** claim, never inflated/excused by response time. **Cross-arm human-effort comparison requires a competitor-side measurement** (screen-capture frame timestamps of prompt display and of input commit); absent it, response-time claims are **Moe-only product bars**, not comparisons.

### 6.4 Rubber-stamp detection (a real gate)

The reading floor is `Φ_stamp = rendered_word_count / WPM_read × safety_factor` (Section 0), computed **only on human user-study sessions** (in scripted runs, timing is the script's, so it measures the script). An approval below `Φ_stamp`, or with no diff-scroll coverage where scrolling is required, is flagged. **Rubber-stamp rate is a named co-gate:** a rate above `ρ_stamp` **voids any human-effort advantage claim** (`G-L4-effort` cannot PASS).

### 6.5 Scripted assistance

All human turns in automated runs come from the frozen, hash-committed script, identical across arms — the same approvals/rejections/unblocks at the same decision points — measuring how many turns each system *demands* while keeping human input controlled.

## 7. Performance and statistics preregistration

Preregistered per Section 0; analysis script committed and dry-run on pilot; pilot data never enter confirmatory estimates or confirmatory-tested margins.

### 7.1 Design

- **Task-paired, run-replicated, interleaved.** Every task run by every arm; `R[s]` replications; analysis on within-task differences. Order randomized/interleaved; timestamp + model snapshot recorded per run (drift → noise, not confound).
- **`N_task` and stratum (hence `R`) frozen at corpus freeze** (Section 0), before any confirmatory run — no data-dependent stratum assignment.
- **Simulation-based power** from a pilot (≈ 5–8 tasks × 10 runs) estimating the two variance components; the numeric `MDE[g]` per gate is committed; pilot-SD uncertainty propagated by resampling variance components → power **bands**; `N_task` frozen where the lower band clears 80–90%. The Bjarnason table (≈ 36/9/2 runs to detect 1/2/5 pp) is a run-level sanity check only.

### 7.2 Endpoints, estimators, and the endpoint-role table

Each rung publishes an **endpoint-role table**: **co-primary gates** (intersection-union — each at its own `α_test`, all must pass, no correction), a disjoint **Holm** confirmatory-secondary family, and a **Benjamini–Hochberg** (`q_BH`) exploratory panel. **One primary test and one interval method per endpoint** (no "or" forking): the primary paired test is the **paired sign-flip permutation**; per-task rates use **Wilson** intervals; aggregates use a **hierarchical bootstrap** (resample tasks, then runs within task; `B_boot` resamples; published seed); the paired-bootstrap and Bayesian-posterior alternatives are labeled sensitivity analyses whose disagreement must be reported.

- **Acceptance rate** (co-primary): per-task success probabilities from `R` runs, paired sign-flip over the per-task difference vector.
- **Wall-clock (`G-L3-speed`) is censoring-aware, and its headline magnitude is defined exactly and comes from the censoring-immune measures — never from a post-treatment accepted subset (same collider discipline as the cost estimand, Section 8.2).** The headline is the ratio **`RMST_OFF(τ) / RMST_ON(τ)`**, where `RMST(τ)` is the **restricted mean time-to-acceptance of the acceptance cumulative-incidence function (the sub-distribution CIF, not a cause-specific estimator)** at truncation `τ`, computed over the **all-pairs** estimand. Because the CIF folds in acceptance *probability*, the headline is **effective time-to-acceptance**, not pure per-attempt latency; the report labels it as such, and "faster" is restricted to the latency component whenever the separately-gated acceptance CIs overlap. the **bootstrap resampling unit is the task** (hierarchical: resample tasks with replacement, then runs within each task; `B_boot` resamples; published seed), giving the ratio's 95% CI. PASS requires the **RMST-at-`τ` difference CI to favor ON** and the **lower 95% CI bound of `RMST_OFF/RMST_ON` ≥ `Λ_speed`** before "1.8×" may be stated. The **"accepted within budget `B[s]`" proportion favoring ON is a separate co-gate** (a per-task binomial), not folded into the ratio. A geometric-mean paired log-time ratio may be reported **only as a labeled secondary** over both-accepted pairs, and **only when the excluded-pair fraction is below a preregistered ceiling AND non-differential across ON vs OFF** (else `UNKNOWN`); it never sets the headline. **Cap-as-observed-time is forbidden.**
- **Reliability headline pass^k** (the orchestrator's core claim) uses the without-replacement unbiased estimator **`C(c,k)/C(n,k)`** (naive foil `p̂^k`); `k` fixed in Section 0; per-task pass^k aggregated via the hierarchical bootstrap. (The pass@k estimator `1 − C(n−c,k)/C(n,k)` is used only where pass@k — "at least one of k" — is separately reported; conflating them inflates reliability ~30× at moderate rates.)
- **Effect sizes with intervals, never bare p or %.** Template: *"Moe completes tasks X% faster than {comparator}, 95% CI [a%, b%]"*, *"acceptance differs by X pp, 95% CI [a pp, b pp]"*.

### 7.3 Non-inferiority

- **`M2_quality` by explicit M1/M2 logic** from an adequately sized **three-arm in-campaign design** (full Moe, weak reference = single-shot no-review agent, comparator): `M1` = lower-95% bound of the incumbent's advantage over the weak reference; `M2 ≤ 0.5·M1`. M1/M2 is used **only** where a weak-reference effect genuinely exists (quality NI). **`G-overhead` uses the per-pair contrast `z_i = (T_moe_i − T_control_i) − max(overhead_frac·T_control_i, overhead_floor_s)`** (the design's floor baked in per pair) and tests **per-task conformance, not an offsettable average**: PASS requires the **upper `(1−α_test)` CI bound on the fraction of tasks with `z_i > 0` ≤ `π_overhead`** (hierarchical bootstrap, task the resampling unit, `B_boot` resamples). This catches a Moe that blows the floor on short tasks even if it is fast on long ones — the mean-of-`z_i` form is rejected precisely because long-task credit could offset short-task violations. This is not an M1/M2 derivation, because in Moe-vs-bare-agent the bare agent *is* the comparator (no placebo analogue). **No pure "≤ 10 %" ratio form appears anywhere.**
- **One-sided `α_test/2` as a CI bound**, stated on the **same scale as its test** (log-ratio margins tested against log-ratio CIs); the CI is **plotted against the margin line**.
- **Three populations:** full ITT (sensitivity only); **primary = mITT** with infra-`UNKNOWN` removed **symmetrically** and per-arm infra rates published (an arm above `ι_infra` is **voided**, not absorbed — infra-`UNKNOWN` is never swept into the failure column, closing the cloud-arm asymmetry); **true per-protocol** excluding preregistered protocol deviations (wrong model, config drift, unauthorized network). NI conclusion must hold across mITT **and** PP.
- **Assay sensitivity, endpoint-matched:** each NI endpoint names a known-worse-**on-that-endpoint** arm the benchmark must distinguish — for the time endpoint an artificially throttled arm (not the bare agent, which is *faster*); failing to detect it renders the NI result inconclusive.

### 7.4 Censoring, failures, no discards

Preregistered outcome taxonomy, fixed before collection:

1. **ADMINISTRATIVE CENSORING** — **the fixed wall-clock cap only** → right-censored at `τ`.
2. **COMPETING TERMINAL EVENT** — token/step-budget exhaustion (fires at a behavior-dependent time; informative on the time axis) → handled in a **cumulative-incidence / competing-risks** framework, not as administrative right-censoring.
3. **PRODUCT-IMPOSED CAP** — e.g. Copilot's 59-min session cap → **non-acceptance-within-budget (a product fact)**, never administrative censoring (the classification is preregistered, not chosen after seeing data).
4. **AGENT FAILURE** — gave up / non-applying patch / failed verifier / protocol failure / **terminated at `τ` while awaiting a decision command beyond the frozen human-assistance script** (the `G-J1` stall case — explicitly excluded from administrative censoring so a system that demands unscripted human input cannot vanish into rule 1) → FAILURE, kept in the risk set as a non-event through `τ` (never informatively censored at its give-up time).
5. **INFRASTRUCTURE FAILURE** — provider 5xx / rate limit / container fault → re-run to `retry_cap`; per-arm retry rate published; residual = infra-`UNKNOWN` (removed symmetrically per Section 7.3, never a failure).

- **Primary time analysis:** competing-risks cumulative incidence of acceptance per arm; **RMST-at-`τ` difference** with a bootstrap CI; plus the **"accepted within budget `B`" proportion** (a clean per-task binomial, censoring-immune, the headline reader wants).
- **No discarded runs.** Two preregistered sensitivity analyses beside RMST (PAR-10; Schmee-Hahn truncated-normal imputation); the conclusion's sign must be stable across all three. Cap-as-observed-time is forbidden in every gate.

### 7.5 Multiplicity and stopping

- **Per-rung hierarchy** (Section 7.2). **Cross-cohort multiplicity:** the L5 conjunction is an intersection-union test across members (each member's NI+superiority must hold — IUT needs no inflation correction because the claim is the conjunction); any **per-comparator** sentence uses **Holm across comparators**. `α_test` per endpoint; the error-rate structure across members is printed in the release report.
- **Fixed `N_task`, no peeking.** Interim looks require a preregistered Lan-DeMets O'Brien-Fleming spending function (+ futility) or anytime-valid confidence sequences (wider intervals); the report states which. Ad hoc replication trimming is optional stopping and is banned; if the full factorial is unaffordable, a preregistered stratified subsample or a coverage-proven adaptive scheme (Pro-Active Inference) is used.

## 8. Cost and token accounting

### 8.1 Cost-class enum

`PROVIDER_REPORTED_COMPLETE` · `PROVIDER_REPORTED_PARTIAL` · `DERIVED_LIST_PRICE` · `SUBSCRIPTION_QUOTA` · `ACTUAL_BILLED` · `UNKNOWN`. **`PARTIAL` on any dimension a cost gate consumes resolves that gate `UNKNOWN`** — never silently treated as complete. **Imputation is permitted only for the self-paired ceiling gate `G-L3-cost` (both arms Moe), imputing the missing dimension at its documented maximum (conservative-against-the-claim). For any cross-arm cost gate (L5 cost non-inferiority, Moe vs a competitor) imputation is forbidden — a consumed-dimension `PARTIAL` on either side resolves the gate `UNKNOWN`** (imputing a competitor's unknown cost at its maximum would shrink the Moe/competitor ratio and flatter Moe, so it is disallowed).

### 8.2 Rules

- **Cost estimand (closes the collider bias):** per (task, arm), **total cost of ALL runs (including failed and censored)** ÷ **number of accepted runs**; paired log-ratio over that quantity with BCa CI. A zero-accepted (task, arm) pair has ratio `+∞`, is **retained and reported**, and **`G-L3-cost` cannot PASS while any such pair exists in the primary stratum**. (This honors "failed runs count" — failed spend is in the numerator — and never conditions on the post-treatment accepted subset.)
- **Cross-arm cost non-inferiority (`G-L5-cost[m]`, per cohort member `m`):** the paired **Moe−`m` cost log-ratio** (same all-runs-over-accepted estimand), NI at margin **`M_cost`** — PASS iff its **upper 95% CI bound ≤ `M_cost`**; `UNKNOWN` iff cross-basis or a consumed-dimension `PARTIAL` on either side; else `FAIL`. **`Γ_cost` (the 5× self-paired ceiling) is never reused as "matching cost."** Each member's cost verdict is printed and AND-ed into `G-L5`.
- **`UNKNOWN` never becomes 0 and never rounds to PASS;** either side `UNKNOWN` ⇒ the gate is `UNKNOWN`.
- **Gates are evaluable within-basis only.** Cross-basis numbers may appear in prose tables labeled approximate but **never feed a PASS/FAIL** — a `SUBSCRIPTION_QUOTA` competitor is not divided into a `DERIVED_LIST_PRICE` Moe figure for a gate.
- One billing mode per product per campaign, named in the row (cache mechanics differ within a product's modes).
- Cost is a **co-primary** endpoint (Section 7.6): tokens + USD (or quota units) per the estimand above, paired log-ratio + BCa, plus a cost-vs-acceptance Pareto plot — orchestration overhead (planner+reviewer+governor) is priced, not just credited its accuracy delta.

## 10. Crash / security test ethics and containment

- **Containment applies to automated benchmark runs.** Synthetic everything (`MOE-FAKE-` prefix; `resource-sim` local; generator emits reserved-domain / invalid-credential strings + pre-run scanner, Section 3.1). Local fault injection only; BENCH-S7 replay hits **only the local Moe daemon**. No provider-control evasion; runs stay within each product's permission model. No pushes to real remotes, no account creation, no purchases, no messages — for the **automated** runs.
- **Cloud-cohort execution reconciled with containment (closes the "unexecutable / convenience-sample" hole):** an **approved fixture-distribution channel** — disposable, clearly-labeled benchmark org/repos created for the campaign — reconciles containment with cloud products' hosted-repo requirement. The **executed-cohort subset is preregistered and sealed at freeze** (per member: run / no-run + reason); the L5 sentence may name only members actually run; cohort selection is a Section 13 threat.
- **Per-member ToS pre-run gate:** before executing any member, record the specific clause relied on for permissibility of **benchmarking-by-a-competitor** (Moe is a direct competitor; several vendors' terms restrict competitive benchmarking or building a competing product), or mark the member **not-executed** with that reason. ToS also governs publication (drop from the public cohort rather than violate terms).
- **User-study safeguards (Section 11) are separate from automated containment:** study-only remotes or branch-protected forks; an ethics-review step; a data-retention period; and a participant cost/ToS-liability statement per the SIGSOFT standards cited. **Moe does not implicitly stage, commit, push, or merge on REVIEW** (the design's delivery is explicit-path, PR/branch-shaped integration with the producing lease epoch verified at acceptance; no agent auto-stage/push, never broad `git add -A`). Any study remote action must therefore be an **explicit, separately authorized command with containment and provenance** — consent is recorded for it, but the remote action never happens as a silent side effect of reaching REVIEW.

## 11. Product user-study protocol

Small-N, directional-only, scoped — because self-reported speed misleads (METR: 24% forecast, 20% believed, **19% slower** measured) and small N cannot support statistical superiority on standardized scales.

- **Target user (one canonical definition everywhere, by needs not architecture):** a solo developer delegating autonomous coding work under local/privacy constraints. The "local control plane" phrasing is dropped as persona-gerrymandering and the persona-definition choice is disclosed as validity threat 26 (Section 13.2).
- **Two arms, claims never blended.** (a) **Formative discovery:** **n ≥ 10 per distinct segment** (the deliverable *is* the problem inventory, so completeness always matters — Faulkner: a 5-user set may find as little as 55%); concurrent think-aloud (Boren-Ramey); real repos permitted here only. (b) **Comparative (timed):** within-subjects, **fixed matched-pair task battery** (equivalent difficulty), **AB/BA counterbalancing of both presentation order and task-condition assignment** (each pair member in each condition for half the participants); order-effect estimate reported **with CI as a limitation**, not as "verification" (n ≤ 15 has negligible power to detect it); **silent blocks** (concurrent think-aloud inflates time — Hertzum 2024); retrospective replay where explanations are needed.
- **Comparator named at freeze:** the strongest COMPARABLE model-matched product (never the analyst's post-hoc pick).
- **Recruitment:** representative solo developers matching the canonical persona; segments (e.g. autonomy-tool-experienced vs not) sized ≥ 5 each with screening that does **not** exclude a declared segment; recruitment criteria/incentives/exclusions preregistered (SIGSOFT).
- **Agent-specific outcomes** (Answer.AI Devin methodology): success/failure/**inconclusive** fixed before runs, plus time-to-abandon dead ends, **blocker-surfacing** (does the system surface the blocker — probing Moe's BLOCKED/report_blocked machinery), and human-intervention count.
- **Instruments:** SUS post-condition (vs the 68 mean / Sauro-Lewis curve), SEQ per task (≈ 5.5), UMUX-Lite with the published SUS mapping where full SUS is too heavy, Raw NASA-TLX for the supervision-workload question only. **Trust:** Jian et al. TIAS (12-item) once per condition; the 3-item S-TIAS **between tasks or in the retrospective replay** (never injected into the silent timed blocks it would inflate and prime; per-gate high-frequency use is outside the instrument's validated envelope); no ad-hoc item edits.
- **Consent/privacy:** written consent before recording, itemizing screen+audio+code capture; "testing the product, not you"; right to withdraw during/after; redaction plan for proprietary code/credentials/keys; explicit consent for agent commits/pushes with the Section 10 study safeguards; ethics review + retention period stated.
- **`G-L4-userstudy` (the L4 non-contradiction gate):** one primary user-study endpoint is preregistered; its paired-difference CI **must not oppose** the benchmark's gate direction (a CI whose sign contradicts the benchmark result ⇒ `G-L4-userstudy` = `FAIL`, blocking L4 — the METR failure mode, 19% slower despite perceived speedup, is exactly what this catches; unresolved ⇒ `UNKNOWN`). This gate is *non-contradiction*, not superiority — it cannot, on its own directional n ≤ 15 evidence, license a superiority claim.

**Claims discipline (what n ≤ 15 supports):** problem inventories (with the Faulkner coverage caveat), SUS/SEQ/UMUX-Lite/TIAS point estimates and — for the comparative arm — the **within-subject paired-difference CI** (derived from the pilot pairing correlation, **not** a one-sample ±10–15-SUS width), qualitative mechanism findings, and **directional reporting = sign + full difference CI, with no directional language when the CI crosses 0** (never a threshold-crossing rule that smuggles in an unlabeled hypothesis test). The comparative N is stated and powered on the pilot correlation. **May not claim:** statistical usability superiority (needs ≈ 20–51+/cell), percentage productivity gains, or generalization beyond the sampled persona. Perceived speedup is reported **only** as a perception endpoint. Every result version- and date-scoped.

### 12.1 Mechanical namespace and reference audit (pre-freeze gate)

Before a campaign is frozen, an automated audit **must pass** (a failing audit blocks freeze; it is not a judgment call):

1. **Every scenario and invariant reference resolves** to a declared ID — every `CORE-I{1..22}`, `CORE-S{1..14}`, and `BENCH-S{1..14}` reference points at a defined member; **no ambiguous bare `S{1..14}` or `I{1..22}` token appears anywhere** in the benchmark (every scenario/invariant token carries a `CORE-`/`BENCH-` prefix; the two namespaces never blur).
2. **Every gate ID resolves** — each `G-*` used is defined, and each defined `G-*` is either wired into a rung or explicitly declared out-of-ladder (`G-expand`); umbrella IDs `G-L3`/`G-L4` equal the AND of their listed sub-gates. **Every comparator-indexed gate (`G-L4-quality[m]`, `G-L4-accept[m]`, `G-L4-effort[m]`, `G-L5-accept[m]`, `G-L5-cost[m]`, `G-L5-effort[m]`) is printed for every model-matched COMPARABLE member `m` and included in the intersection-union AND** — a missing member verdict makes the rung `UNKNOWN`, never silently PASS.
3. **The rung→gate inventory is complete and PASS/FAIL/UNKNOWN is exhaustive** — every rung's decision rule and the Section 12 inventory list the identical gate set; every gate has all three verdicts defined; no rung can print `PASS` while any listed (or indexed-member) gate is `UNKNOWN`/`FAIL`.
4. **Every load-bearing threshold is a Frozen-Constants-Table symbol** — no gate consumes an inline literal for a tunable threshold; an unset symbol forces `UNKNOWN`.
5. **CORE coverage cannot be reduced by benchmark configuration** — no benchmark setting, subsample, budget, or stratum choice narrows the CORE `ScheduleCoverageManifest` obligation that `G-L1` consumes; the manifest's frozen minima are a floor the benchmark may exceed but never lower.
6. **Every non-inferiority gate's CI tail matches its endpoint's worse-direction** — for a higher-is-better endpoint (acceptance) NI bounds the **lower** CI tail (`lower CI ≥ −margin`); for a worse-is-higher endpoint (cost, failure-rate, overhead) NI bounds the **upper** CI tail (`upper CI ≤ margin`). A gate whose tail does not match its endpoint direction is a freeze-blocking defect (this is the check that would have caught the acceptance-gate sign inversion).

## 13. Non-goals and validity threats

### 13.1 Benchmark non-goals

Not a leaderboard/marketing generator; not a general capability benchmark (measures orchestration, safety, human-effort on a small curated corpus); not a superiority proof at any rung the N cannot support (L4/L5 usability evidence is directional); does not benchmark members whose ToS forbids competitive benchmarking or that were not in the sealed executed subset; does not test model capability in isolation (always the triple); does not certify security (BENCH-S7 fences Moe's own daemon).

### 13.2 Validity threats (every one published in the report; each has a protocol mitigation, not just disclosure)

1. **Contamination/memorization** — synthetic post-cutoff fixtures + per-campaign surface regeneration + held-out oracles + externally-authored surprise slice.
2. **Author-side harness overfitting** — corpus/oracle/prompt authors + annotators independent of the Moe team; Moe-commit-freeze vs corpus finalization; externally-authored held-out slice (Section 3.1).
3. **Harness/config attribution** — capability = triple; Moe at shipped defaults for primary; tuned-Moe labeled secondary.
4. **Self-authored rubric bias** — externally-authored calibration key + independent raters/adjudicator every campaign + per-campaign cross-check.
5. **Blinding leakage** — measured via the arm-identification test with a `β_blind` downgrade gate; arm-identifying oracle detail withheld from reviewers.
6. **Model mismatch** — matching triple; effort-locked/snapshot-`UNKNOWN` bracketed or flagged.
7. **Cost incommensurability** — classes never divided across bases; `UNKNOWN`/`PARTIAL` never zeroed or PASSed.
8. **Small-N usability** — directional only; paired-difference CIs; claim ceiling stated.
9. **Perception ≠ reality** — perceived speedup only as a perception endpoint (METR).
10. **Version/pricing drift** — per-product drift sentinels + partial invalidation (drop the drifted arm), not vacuous-or-fatal whole-campaign rules.
11. **Harness/infra flakiness** — distinct outcome class, `ι_infra` arm-void ceiling, symmetric infra-`UNKNOWN` removal; never contaminates the denominator.
12. **Capability-absent asymmetry** — Moe-only scenarios in the capability matrix, never speed/quality wins, never L5 evidence.
13. **Corpus one-directionality** — BENCH-S1–BENCH-S12 are Moe-shaped (safety hooks + decomposition); mitigated by scoping L5 to the COMPARABLE subset **and by the required (not optional) bidirectional scenarios BENCH-S13 (ordinary non-decomposable work) and BENCH-S14 (competitor-anchored, Moe expected ABSENT/ADAPTED) of Section 3.6**, which `G-L5` requires in the executed set and over which the quality-NI gate runs — so "no worse in quality" is tested on ordinary work, not only Moe-favorable tasks.
14. **Cohort selection / survivorship** — executed subset sealed at freeze; `C_min` floor; account/payment shrinkage named; L5 names only run members.
15. **Operator-skill asymmetry** — vendor-doc runbooks + familiarization logs + external expert operators for primary runs.
16. **Campaign-level file-drawer** — public campaign registry before results; abandoned campaigns reported.
17. **Sponsor / demand characteristics** — vendor-run study; disclosed; independent moderation where feasible.
18. **Differential comparator familiarity** — distinct from carryover; screened + reported; counterbalanced.
19. **Corpus-constructed decomposability** — BENCH-S2 is built decomposable; the report states this quantifies a corpus-defined phenomenon and does **not** estimate what fraction of the target user's real work is decomposable.
20. **Scripted-human unrealism** — automated human-effort numbers from a fixed script may not transfer to real humans; the user study is the ecological check.
21. **Asymmetric carryover** (within-subjects study) — design-irremovable; acknowledged.
22. **Execution-locale confound** — cloud provisioning time separated (time-to-first-agent-action); L3 headline scoped to matched locale.
23. **Network-locale confound** — stratified analysis, not asserted parity.
24. **Cloud-arm non-replicability** — excluded from the replication gate; date-stamped; L5 scoped to replicated arms.
25. **Competitor ToS on execution + publication** — per-member pre-run ToS gate; drop rather than violate.
26. **Persona / target-user framing (persona-gerrymandering)** — defining the target user by Moe's architecture ("local control plane") would pre-tilt "best for the target user" toward Moe and against cloud competitors by construction. Mitigation: the target user is defined by **needs, not architecture** (a solo developer delegating autonomous coding work under local/privacy constraints — Section 11), one canonical definition used everywhere, and the persona-definition choice is itself disclosed as this threat.

## 15. Closing

"Moe is the best tool" is now a claim that can be earned or refused, not asserted. The ladder's grammar is permit-list (only enumerated, scoped sentences are sayable; L5 requires cohort-wide non-inferiority-plus-superiority as an intersection-union test, ≥ `C_min` executed model-matched members, and a criterion-bound replication — not merely that artifacts exist). Every load-bearing constant is frozen in one table before data are seen; every gate has a stable ID wired to a rung in the release template, so no rung prints PASS while a sub-gate is UNKNOWN. The statistics are censoring-aware (RMST + accepted-within-budget, competing risks for token caps, product caps as non-acceptance), the pass^k estimator is the without-replacement one, cost is a per-all-runs-over-accepted co-primary where UNKNOWN and PARTIAL never round to PASS and cross-basis never feeds a gate, and non-inferiority carries M1/M2 only where a weak reference exists with an endpoint-matched assay-sensitivity arm. Fairness is enforced by freezing the classification/prompts/assistance/budgets/executed-cohort at preregistration, by independent corpus authors and raters, by measured (not asserted) blinding, by model-matching on the full triple with Moe at the comparator's effort and shipped defaults, and by scoring competitor non-adoption of Moe's workflow as a capability fact rather than a failure. The user study claims only what n ≤ 15 and a vendor-run study support, with perceived speed quarantined as a perception endpoint. What the spec deliberately refuses to do — run anything, buy anything, trust a single number, or let its own author's bias pass unmeasured — is the point.
